# 終了コード { #exit-codes }

smates の終了コードで、「コードを直す」（1）のか「セットアップを直す」（2〜4）のかを区別できます。すべてのコマンドで同じコードを使います。

| コード | 意味 | 対処 |
|---|---|---|
| `0` | 成功: テストが通った、または実行するものがなかった。 | 何もしなくてかまいません。 |
| `1` | テストが失敗した（ランナーの終了コードにかかわらず）。中断された実行、`smates doctor` のチェックの失敗、予期しないエラーも 1 です。 | コードかテストを直します。 |
| `2` | 使い方の誤り: コマンドラインが不正。 | コマンドラインを直します（`smates <command> -h`）。 |
| `3` | 設定のエラー。 | `smates.yml` を直すか（`smates config ...`）、指定した名前を直します（`smates list`）。 |
| `4` | 環境の問題。 | `smates doctor` を実行します。失敗したチェックごとに対処法が示されます。 |

## 1: テストが失敗した { #1-tests-failed }

`smates run` は、ランナーのバッチが 1 つでも失敗すると 1 で終了します。失敗したテストがある場合のほか、どのテストが失敗したか分からないまま 0 以外で終了した場合（`TestMain` が 1 で終了した、後処理のエラー、カバレッジのしきい値など）も含みます。ランナー自身のコード（pytest の 2 など）はそのまま返さず、[`--report`](cli.md#smates-run) の JSON の `exit_code` とまとめに記録します。

Ctrl-C、SIGTERM、SIGHUP で止めた実行も 1 で終了します。実行できた分は記録され、実行されなかったテストは選択されたまま残ります。

## 2: 使い方の誤り { #2-usage-error }

- 未知のコマンドやフラグ、引数の不足（ファイルを指定しない `smates why` など）
- 不正なフラグの値（`--shard 5/4`、`--output verbose`、`--orphans maybe`、未知の `--format`）
- 組み合わせられないフラグ（[`smates run`](cli.md#smates-run) を参照）
- 実行に含まれないテストを指定した `--add`
- どのコミットも指さない `--base`（shallow clone ではない場合）

## 3: 設定のエラー { #3-configuration-error }

- `smates.yml` を解析できない、未知のキーや不正な値がある
- 未知のランナー、または解析できないスイートのコマンド
- スイートがまったくない（設定にも自動検出にもない）
- 設定に存在しないスイートやテストをコマンドラインで指定した（`--suite`、`--only`、`smates deps <test>`）

## 4: 環境の問題 { #4-environment-problem }

- git がない、またはディレクトリが git リポジトリではない
- スイートのコマンドを起動できない（`PATH` にない、実行権限がない）
- `npx` や `bunx` がダウンロードしなければならないツール（`node_modules/.bin` にない）: 先に依存をインストールしてください
- 記録する実行で、どのテストも結果を報告する前にランナーのプロセスが 126 または 127 で終了した（シェルの「実行できない」「コマンドが見つからない」。`npm test`、`yarn`、`pnpm exec`、`sh -c` 経由の場合も含む）
- ステートを保存できない（共有ステートのロックを別の worktree の実行が持っている、など）
- スイートの [`requires`](configuration.md#requires)（データベース、ブラウザなど）がこの環境で満たされない
- shallow clone に `--base` がない（`fetch-depth: 0` や `git fetch origin <branch>` で取得してください）、または選択中に git がベースとの差分の取得やリポジトリの一覧の取得に失敗した

ランナーを起動できなくても、また前提条件を満たさなくても、ほかのスイートは実行・記録されます。そのスイートのテストは選択されたまま残ります。smates は先に失敗の内容（出力、まとめ）を表示してから 4 で終了します。`--output failures` モードでは、まとめの行が `PASSED` ではなく `NOT STARTED` になります。

??? note "詳細: 126/127 がテストの失敗として扱われる場合"
    126/127 の扱いは、テストごとの結果を報告するランナーを記録付きで実行した場合に限ります。`--no-record` のときや `custom` ランナーでは、テストが実際に動いても何も報告されないことがあるため、126 や 127 での終了はテストの失敗（終了コード 1）になります。

### 失敗とセットアップの問題が重なったとき { #when-failures-and-setup-problems-meet }

テストの失敗が優先されます。同じ実行でほかのスイートのテストが失敗していれば、smates は 1 で終了し、環境の問題は補足として表示します。ステートを保存できなかった場合も同様で、テストが失敗していれば 1、そうでなければ 4 です。

## レポートと CI の出力 { #in-reports-and-ci-outputs }

| 場所 | 値 |
|---|---|
| `smates run --report` の `exit_code` | ランナーの終了コードのうち最も悪いもの。テストの失敗がなく環境の問題だった場合は `4`。 |
| `smates run` が `$GITHUB_OUTPUT` に書く `exit-code` | `exit_code` と同じ。 |
| GitHub Action の `exit-code` 出力 | smates コマンド自体の終了コード（テストの失敗なら `1`）。 |
| `smates hook claude-stop`、`codex-stop` | `0`（許可、またはテスト失敗時に JSON の判断でブロック）か `1`（smates 自身のエラー。エージェントではなくあなたに表示されます）。2 で終了することはありません。満たされない `requires` や時間の上限で外れたテストは、エラーではなく 0 で、stderr に 1 行表示します。 |
| `smates hook run pre-push`、`pre-commit`（git フック） | テストが成功したとき、または外れたテストがこのマシンにないものを必要とするものだけのとき（満たされない `requires`。stderr に 1 行表示し、push やコミットは続行し、それらのテストは CI のために選択されたまま残ります）は `0`。テストが失敗したときは `1`。それ以外は `smates run` と同じコードです。 |
| `smates hook install`、`uninstall` | 完了したら `0`。コマンドラインが不正なら `2`。smates が編集できない設定ファイル（JSON ではない、想定外の構造。手で直してください）なら `3`。それ以外のセットアップの失敗（ファイルを読み書きできない、フックのスクリプトがすでにある）なら `4`。 |
