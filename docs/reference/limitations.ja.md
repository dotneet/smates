# 制限事項 { #limitations }

smates に見えないものと、その対処法をまとめたページです。多くは `smates.yml` で回避できます。残りはまれなので、定期的な全件実行（`smates run --all`、または CI のデフォルトブランチ）でカバーできます。

## トレースが届く範囲 { #what-tracing-reaches }

**別プロセスのサーバー。** トレースはテストプロセスとその子プロセスを追いますが、テストがネットワーク越しに使うサーバー（docker compose、別に起動したバックエンド）は追いません。そのため、サーバーのコードを変えてもそれらのテストは選択されません。
対処: サーバーのコードを `depends_on` か `serves` で宣言します。[サーバーを叩くテスト](../guides/servers.md) を参照してください。

**リポジトリ外のデータ。** テストがデータベースや外部サービスから読むものは追跡されません。
対処: 依存するファイルを `rules` か `inputs` で宣言するか、そうした変更を [オーファン](../guides/orphans.md) としてエージェントに判断させます。テストの前に適用するスキーマには、`reaches` 付きのルールでデータベースのヘルパーを import するテストにマイグレーションを依存させられます。ただし、ルールが挙げていない方法で接続するテストは、マイグレーションの変更では実行されなくなります（[データベースを使うテスト](../guides/configuration.md#tests-backed-by-a-database) を参照）。

**ブラウザで動くコード。** ブラウザで実行されるコード（vitest のブラウザモード、Playwright）は、静的な import グラフでしかカバーされません。

**中を見られないコマンド。** シェルスクリプト、`grep`、`cat` などのコマンドは、コマンドラインから解析します。中を見られないコマンド（`make`、コンパイル済みのバイナリ）を実行すると、テストはそのディレクトリ配下のすべてに依存することになり、必要以上に実行されます。そのディレクトリの外のパスは、引数やオプションの値に現れる場合にだけ見えます。コマンドラインが記録されない Go のテストの子プロセスでは、まったく見えません（パッケージのディレクトリから実行する `sh -c "cat ../../testdata/x"` など）。Go のテストが終了前に削除したプログラム（`t.TempDir()` にビルドしたもの）は検出されず、Go のテストが読むだけの実行ファイルはプログラムの起動として数えます（依存が増えることはあっても減ることはありません）。[子プロセス](../guides/runners.md#child-processes) を参照してください。

**型だけの import。** vitest と bun のスイートでは、実行前に TypeScript が消す import があっても、テストはその import 先のモジュールに依存しません。そのため、テストが型としてしか使わないモジュール（`src/types.ts`）を変えても、どのテストも選択されず、オーファンにもなりません。消える import は次のとおりです。

- `import type …` と `export type … from` の宣言（常に）
- `import { type A, type B } from` と `export { type A } from`（すべての指定子に `type` が付いたもの）。ただし、そのファイルに適用されうる `tsconfig.json` が `verbatimModuleSyntax`、`preserveValueImports`、`importsNotUsedAsValues` を設定している場合、smates が読めない設定を extends している場合、その tsconfig 自体を読めない場合は除きます。これらの設定ではこの import が `import {} from` として残り、モジュールが読み込まれるからです。

`typeof import("./x")`、`import("./x").T`、`type A` と値が混在するリスト、`.js` や `.vue` などの中の import は、いずれも依存のままです。また、型チェックが走りうる実行では、型だけの import も依存として残します。具体的には、スイートのコマンドが `vitest`（または `bun test`）を直接実行していない場合（`npm test`、`&&` でつないだコマンド）、コマンド・`--` 以降の引数・スイートの `env` に `typecheck` や `tsc` などが含まれる場合、スイートの vitest/vite の設定ファイルやそれが import するファイルに `typecheck` の設定（または上記のコンパイラオプション）がある場合、smates が vitest の設定を見通せない場合（ワークスペースファイル、他の設定ファイルをパスで指す `projects:`・`workspace:`・`extends:`、vitest・vite・その公式プラグイン・Node の組み込みモジュール以外のパッケージの import。共有のプリセットなど）、スイートに `*.test-d.*` / `*.spec-d.*` ファイルがある場合です。jest（ts-jest は型エラーを報告します）、`node --test`、custom のスイートでは常に残します。以前のバージョンの smates で記録したテストは、次に記録されるまでその依存を持ち続けます。
型チェックはテストの実行ではないので、CI では `tsc`（または使っている型チェッカー）を動かし続けてください。

## 環境変数 { #environment-variables }

**名前を指定した読み取りだけが見えます。** 変数が依存になるのは、コードが `process.env`（Bun の `Bun.env` や、Bun での `import.meta.env` は対象外）、`os.environ`、Go の `os.Getenv` / `os.LookupEnv` で読んだときです。ランタイム自身が参照するもの（日付の `TZ`、ロケール、`GODEBUG`）、ネイティブコード、`syscall.Getenv`、smates がトレースできないコマンド（シェルスクリプト、バイナリ）は見えません。

**環境の列挙は追跡されません。** その後で一部の変数だけを使う場合も同様です: `Object.entries(process.env).filter(...)`、`os.environ` に対する辞書内包表記、pydantic-settings などの設定ローダー。この場合、`MYAPP_URL` を変えても（新しい `MYAPP_*` を追加しても）何も選択されません。`env_track` は名前で読まれる変数の無視を解除するだけなので、助けになりません。対処:

- 変数を名前で読む（`process.env.MYAPP_URL`、`os.environ["MYAPP_URL"]`）
- スイートの `env:` で設定する（値を変えるとスイートが再実行されます）
- テストが読むファイルから読み込む（dotenv ファイルはファイルの依存になります）
- 環境を変えた後に `smates run --all` を実行する

**Go の `t.Setenv`** は元に戻すために以前の値を参照するので、変数を設定するテストも外側の値に依存したままになります。必要以上に実行されることがあります。

**値は SHA-256 のハッシュで保存されます。** ステートファイルを読める人は、推測しやすい値（弱いパスワードなど）を確かめられます。
対処: そうした変数は `env_ignore` に入れます。

[環境変数](../guides/environment.md) を参照してください。

## 粒度 { #granularity }

**ユニットはテストファイルです**（Go ではパッケージ、`granularity: func` ではテスト関数）。モジュールのどこを変えても、それを読み込んだすべてのテストが再実行されます。Python では、モジュールが import 時やキャッシュの裏で読むデータは、そのモジュールに属します。

**Go のテスト関数**（`granularity: func`）:

- 記録にはテスト関数ごとに 1 プロセスかかるので、デフォルトブランチの全件実行が遅くなります。選択的な実行では、選択された関数だけを起動します。
- 記録中、関数どうしはプロセスを共有しません。同じパッケージの別のテストがメモリ上に残した状態に頼るテストは、`go test` のときと動作が変わります。
- 実行されなくても意味を持つコード（インターフェースを満たす、実行されないメソッド）は宣言を通じてカバーされます。リフレクションだけで実行されるコードはカバーされません。
- 試験のパッケージ自身の宣言は、型情報なしに名前でたどります。複合リテラルのキー（`{name: ...}`）は、同じ名前の宣言を使うものとして数えます（マップのキーに使う定数かもしれないため）。実行が増えることはあっても、減ることはありません。パッケージレベル変数の初期化式にあってコードを実行しうる呼び出し（型リテラル・事前宣言された型・同じファイルの型への変換、`(*T)(nil)`、`len` などの組み込み関数、`errors.New`、`fmt.Errorf`、`time.FixedZone`、コンパイルできるリテラルのパターンを渡す `regexp.MustCompile` 以外）があると、その変数はすべてのテストの依存になります。
- すべてのテストが呼ぶヘルパーや、すべてのテストが届く型（サーバーの構造体など）は、すべてのテストの依存です。ヘルパーの中や、その型のフィールド・メソッドセットを変更すると、すべてのテストが選択されます。
- 他のパッケージの宣言はファイル単位で数えます。import するパッケージで定数・型・シグネチャを変更すると、それを import するパッケージのすべての関数が選択されます。

[Go のテスト関数単位の選択](../guides/go-test-functions.md) を参照してください。

## ランナー { #runners }

**ランナーへの引数はテストを絞り込むことがあります。** ランナーにそのまま渡す引数（`smates run -- -t name`）はテストをスキップさせる可能性があるため、こうした実行ではテストを成功として記録しません。
対処: 常に使うフラグはスイートの `command` に書きます。

**スキップしたテストは成功として扱われます（Go のテスト関数を除く）。** 専用のプロセスで記録する Go のテスト関数（`granularity: func`）は、自分をスキップすると未証明として記録され、再実行されます（[スキップしたテスト](../guides/go-test-functions.md#skipped-tests) を参照）。それ以外ではスキップは成功です。すべてのテストがスキップした Go のパッケージ（`granularity: package`、または全体として記録されたパッケージ）、pytest の `skip`/`xfail`、すべてのテストがスキップした vitest や jest のファイルが該当します。こうしたテストは、依存が変わるまで再実行されません。ただし、スキップの条件が読み取った環境変数（依存になる）や存在を確かめたファイルなら別です。
対処: `volatile` に挙げるか、`max_age` を設定します。

**時刻は追跡されません。** 日付や時刻で結果が変わるテストは、時間が経っただけでは選ばれません。
対処: `volatile` に挙げる（毎回実行する）か、`max_age` を設定して記録した実行を期限切れにします。

**Jest** は、ワーカーを使い回さない設定でも、まれに 2 つのファイルを同じワーカーで続けて実行します。その場合は両者の依存がマージされます。正しさは保たれますが、精度は下がります。
対処: `isolate: true` で正確になります。代わりに、記録中はファイルごとに jest を起動します。

**ランナーのキャッシュ**（Vitest の `fsModuleCache` など）は smates の視野の外です。CI で復元したキャッシュは、smates の有無にかかわらず、キャッシュなしの実行なら見えたはずの失敗を隠すことがあります。

**3.12 より前の Python** は `sys.setprofile` でトレースするため、記録中はテストが目に見えて遅くなります。Python 3.12 以降は `sys.monitoring` を使い、オーバーヘッドは小さくなります。後から `sys.setprofile` で設定したプロファイラー（3.12 より前）は、smates のトレーサーを置き換えてしまいます。

**coverage.py の `sysmon` コア。** smates はテストが切り替わるたびに監視イベントを有効にし直すので、coverage.py のイベントも再設定されます。結果は変わりませんが、テストごとに一部の処理をやり直すことになります。

**コマンド内で設定される `NODE_V8_COVERAGE`。** コマンドが自分で設定すると（`env NODE_V8_COVERAGE=... node`、それを export するスクリプト）、その下のプロセスが実行するコードが smates から見えなくなり、静的グラフでしかカバーされません。
対処: 環境かスイートの `env:` で設定します。

**c8** は smates の記録中に `coverage/tmp` を書かないので、後から実行する `c8 report` には読むものがありません。
対処: c8 に同じコマンドの中でレポートさせます。

[言語とランナー](../guides/runners.md) を参照してください。

## ファイルとファイルシステム { #files-and-file-systems }

**実行権限が付くだけの変更**（内容を変えない `chmod +x`）では何も選択されません。古い smates が書いたステートはすべてのファイルを実行権限なしとして記録しており、両者を区別できないためです。実行権限が外れる変更（`chmod -x`）は、現在のバージョンが書いたステートがその権限を記録していれば変更として扱われます。古い smates のステートに対しては、次に記録するまで気付かれません。

**シンボリックリンク経由のモジュール。** Node や Bun がシンボリックリンク経由で読み込むモジュールは、リンク先としてだけトレースされます（ランタイムが先にリンクを解決するため）。そのため、リンクの向き先を変えるとオーファンになることがあります。リンク経由で読むファイル（`fs`、`open`、Go の `os.Open`）は、リンクにも依存します。

**大文字小文字を区別しないファイルシステム。** ディスク上のファイルと大文字小文字が異なる import は、import に書かれた綴りで記録されるため、そのファイルの変更と一致しないことがあります。

**実行中に編集された git 管理外の入力。** テストの実行中に手で編集した git-ignored のファイルは新しい内容で記録されるため、その編集では何も選択されません。[設計](../DESIGN.md) を参照してください。

## プラットフォーム { #platforms }

**Windows。** CLI はビルド・実行でき、GitHub Action も `windows-latest` で動きますが、トレースを検証しているのは Linux と macOS だけです。
